# 平台功能与设计说明

## 1. 项目定位

AI 学术鉴伪系统面向学术内容诚信治理场景，提供自动检测、人工复核、组织管理和审计统计能力。平台支持编辑/发布者提交学术材料进行检测，支持专家对疑似问题内容进行人工复核，并支持管理员完成组织、用户、资源、审核申请、日志和统计管理。

## 2. 用户角色

| 角色 | 登录入口 | 主要能力 |
|---|---|---|
| 发布者 / 编辑 | 用户端 | 上传学术材料、提交检测、查看历史与报告、发起人工审核、查看审核汇总、反馈与举报 |
| 审稿人 / 专家 | 用户端 | 查看人工审核任务、提交七项评分与最终结论、查看个人审核记录 |
| 管理员 | 管理端 | 用户与组织管理、审核申请审批、任务与资源治理、日志审计、统计看板、通知广播 |

用户端路由根据登录角色隔离：审稿人不能进入发布者的检测页面，发布者不能进入专家审核任务池。管理端使用独立登录入口，要求用户角色为 `admin`。

## 3. 核心业务功能

### 3.1 学术材料上传与资源管理

平台支持上传图片、PDF、压缩包等资源。后端统一记录源文件 `FileManagement`，并为可检测图片生成 `ImageUpload` 记录。PDF 中的图片可被提取后进入图像检测链路。

资源管理能力包括：

- 上传文件。
- 查看文件详情。
- 查看文件中提取的图片。
- 更新文件标签。
- 删除上传文件或图片记录。
- 管理端查看全部资源。

### 3.2 图像鉴伪检测

发布者选择图片后提交图像检测任务。后端生成 `DetectionTask`，组织图片批次并调用 AI 服务。检测完成后生成 `DetectionResult` 和 `SubDetectionResult`，展示总体结论、置信度、子方法结果、EXIF/ELA/LLM 辅助信息和报告。

图像检测支持：

- 普通模式、加急模式、LLM/精准模式等提交参数。
- 任务状态查询。
- 用户任务列表。
- 任务结果列表、异常结果列表、正常结果列表。
- 单条检测结果详情。
- 任务级和图片级 PDF 报告下载。
- 删除检测任务。

### 3.3 论文检测

论文检测面向 PDF 文件。当前实现边界为：论文入口仅支持 `.pdf`，不支持直接上传 DOCX 作为论文检测输入。

后端处理流程：

1. 上传 PDF。
2. 使用 PyMuPDF 提取文本。
3. 清洗文本并切分段落。
4. 生成 `paper-preprocess-v1` AI 输入。
5. 创建 `DetectionTask(task_type='paper_aigc')` 或 `DetectionTask(task_type='resource_check')`。
6. 异步执行检测，完成后保存 JSON 结果并生成统一报告。

论文相关能力包括：

- 论文 PDF 上传。
- 论文 AIGC 检测提交、状态查询和结果查询。
- 学术资源规范性检查提交、状态查询和结果查询。
- 失败任务错误信息记录。

### 3.4 Review 文本检测

Review 检测用于对评审意见文本进行自动鉴伪，区别于“人工审核”。

当前支持：

- 在线输入文本。
- 上传 `.txt` 文件。
- 编码标准化、BOM 清理、控制字符清理和空白归一化。
- 生成 `review-preprocess-v1` AI 输入。
- 创建 `DetectionTask(task_type='review_detection')`。
- 查询任务状态和检测结果。

### 3.5 人工审核闭环

人工审核是平台的核心协同流程，用于对自动检测结果进行专家复核。

流程如下：

1. 发布者针对检测任务或检测结果发起人工审核申请，填写理由并选择审稿人。
2. 管理员在管理端查看申请详情。
3. 管理员审批申请：通过后生成审稿人的 `ManualReview` 任务，拒绝后记录原因。
4. 审稿人在用户端任务池查看任务。
5. 审稿人对图片提交七项评分、理由、标注点和最终真假结论。
6. 发布者查看人工审核进度、审核汇总和报告。

核心状态包括：

| 状态字段 | 含义 |
|---|---|
| `ReviewRequest.status2` | 管理员审批状态：`pending`、`accepted`、`refused` |
| `ReviewRequest.status1` | 审核流程状态：`pending`、`in_progress`、`completed` |
| `ManualReview.status` | 专家任务状态：`undo`、`completed` |

### 3.6 管理端治理

管理端围绕平台治理与可观测性设计，主要包括：

- 管理员登录与管理员详情。
- 用户分页查询、创建、更新、删除和权限设置。
- 发布者与审稿人关系管理。
- 文件和图片资源管理。
- 人工审核申请列表、详情、审批和删除。
- 用户操作日志查看、删除和导出。
- 管理端任务汇总和所有用户任务查询。
- 看板统计：标签分布、发布者排行、组织排行、日活用户、每日任务数、每日审核申请数、每日完成人工审核数、子方法分布。
- 通知广播。
- 用户举报处理。
- 检测模型配置与检测日志。

### 3.7 组织与权限

平台支持组织维度的用户与额度管理：

- 用户通过邀请码注册为发布者或审稿人。
- 组织可提交申请，由管理员审核。
- 管理端可直接创建组织。
- 组织拥有 LLM 和非 LLM 检测额度。
- 组织权限可按角色配置。
- 管理员可查询组织列表、组织详情、邀请码、删除组织和上传组织 logo。

### 3.8 通知、反馈、举报和综合报告

平台补充了协作治理能力：

- 通知列表、未读数量、全部已读、单条已读和管理员广播。
- 对人工审核结果进行点赞或评论。
- 社区反馈流。
- 用户举报提交与管理员处理。
- 综合鉴伪报告生成和下载。
- 多模态批量融合接口。
- 检测模型目录、用户偏好和管理员模型配置。

## 4. 系统架构

系统采用前后端分离与 AI 服务独立部署的结构：

```text
用户端前端 / 管理端前端
        │
        ▼
Django 后端 API（认证、权限、任务、资源、报告、日志）
        │
        ▼
AI HTTP 服务（图像检测主链路，论文/Review 文本检测扩展）
        │
        ▼
模型注册表、检测方法、最小可运行模型
```

### 4.1 前端

- 用户端：提供发布者检测、历史、人工审核申请、专家任务池等页面。
- 管理端：提供工作台、任务、资源、成员、组织、审核、日志和统计页面。

### 4.2 后端

Django 后端提供统一 `/api/` 业务接口，负责：

- JWT 登录认证与权限控制。
- 数据模型持久化。
- 文件上传、PDF 和文本预处理。
- 检测任务创建与状态管理。
- 调用 AI 服务。
- 报告生成。
- 通知、日志和统计。

### 4.3 AI 服务

AI 服务为独立 HTTP 服务，默认本地端口 `8010`。主要接口包括：

- `GET /health`
- `POST /api/v1/image-detection/batches`
- `POST /api/v1/paper-detection/batches`
- `POST /api/v1/review-detection/batches`
- `GET /api/v1/admin/model-registry`

图像检测是当前主链路；论文和 Review 文本检测接口已在 AI 服务侧保留扩展入口。

## 5. 数据模型概览

| 模型 | 说明 |
|---|---|
| `OrganizationApplication` | 组织申请 |
| `Organization` | 平台组织、检测额度和组织资料 |
| `InvitationCode` | 组织邀请码 |
| `User` | 用户账号、角色、组织、权限、头像、密码重置 |
| `PublisherReviewerRelationship` | 发布者与审稿人的关联关系 |
| `FileManagement` | 上传源文件 |
| `ImageUpload` | 从源文件中得到的图片资源 |
| `DetectionTask` | 统一检测任务，支持图像、论文 AIGC、资源检查、Review 检测 |
| `DetectionResult` | 图像检测总体结果 |
| `SubDetectionResult` | 子检测方法结果和 mask 数据 |
| `ReviewRequest` | 人工审核申请 |
| `ManualReview` | 审稿人的人工审核任务 |
| `ImageReview` | 单图人工审核七项评分、理由、标注点和结论 |
| `Feedback` | 人工审核反馈/点赞/评论 |
| `Log` | 用户操作日志 |
| `Notification` | 通知 |
| `UserReport` | 用户举报 |
| `DetectionModelConfig` | 检测模型配置 |

## 6. 当前实现边界

- 前端不直接调用 AI 服务，所有业务调用都经过 Django `/api/`。
- 论文检测入口仅支持 PDF；Review 检测支持在线文本和 `.txt` 文件。
- 图像检测是最完整的 AI 主链路，论文和 Review 文本检测具备预处理与任务链路，并通过统一结果文件和报告机制承载结果。
- 接口中保留少量历史兼容路径，但课程组验收和文档说明以 `APIs/current-project-api.md` 为准。
